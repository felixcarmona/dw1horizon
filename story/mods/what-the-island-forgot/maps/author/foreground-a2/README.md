# Foreground segmentation, screens 312–322

The numbered JSON files record the full-resolution generated source art (with its SHA-1), its exact crop into the native map image, the SAM ViT-H object boxes and positive/negative points, the selected scores, and the approved RGBA placement. `records` contains active foregrounds; `reviewed_unused` documents a rejected or redundant candidate. A screen with no reachable rear overlap has no active records. No player-disc pixels are stored here.

Run `maps/author/segment-depth-a2.py --checkpoint PATH_TO_sam_vit_h_4b8939.pth --out BUILD_DIR [SCREEN ...]` from the repository root, using a Python environment with torch, segment_anything, OpenCV and the project raster module. The source images must be present under `art/full`. The model is loaded once and uses three CPU threads; each full-resolution screen is encoded once. Output RGB always comes unchanged from that screen's native art. Placement and collision live in `maps/foreground`; approved RGBA pieces live in `art/foreground`.

Most objects use the selected SAM mask with speck/component cleanup. The thin lattice assemblies additionally use the recorded full-resolution rust/floor colour seeds and GrabCut within SAM's proposal to remove floor between bars. Separately prompted drum surfaces and dark interiors preserve opaque metal without filling the real gaps in the lattice. The notebook is a separate SAM part merged with its console. These steps change alpha only. `fill_holes` applies only where recorded (solid faces); openings between structural bars remain transparent.
