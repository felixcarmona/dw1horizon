# Data sources: the committed JSON is the source of the build

For the whole game, the committed JSON files are the source of truth: the build starts from nothing and puts in
everything the JSON describes, for every numeric domain. Never committed: models, textures, sounds, the dialogue and
description text, disc files.

"From zero": per domain, the build writes the game's table from the files and never keeps the disc's value; **a file
that does not exist is a thing the game does not have** (its id stays, with an empty row: the tables and the scripts
are indexed by number). `content/` and `story/base` are published in the release bundle (`dwpatch.py make_bundle`)
and are owned source: `story/base` is not regenerated by itself (only when the folder is missing, or by
`dws story-base --refresh`). The extractors stay, so every folder can be made again from a disc.

## Domains

| Domain | Where | Source | Removal |
|---|---|---|---|
| Species (stats, techniques lists, raise data, voices, training rows, drops, models' sizes) | `content/species/` | **JSON** (`species.py`) | delete the file |
| Evolution of the imports and the DW1 enemies made partners | `content/species/*.json` `evolution` | **JSON** | via the species |
| Evolution rows of the 147 species of the executable's tables (requirements, gains, `EVOLUTION_PATHS` slots) | `content/species/*.json` `evolution` | **JSON** | a deleted species leaves every list |
| Techniques (`MOVE_DATA`, `MOVE_LEARN_CHANCES`) | `content/techniques/` (122) | **JSON** (`content.py`) | delete the file |
| Items (`ITEM_PARA`: name, price, merit, order, colour, droppable; `EVOLUTION_ITEM_TARGET`) | `content/items/` (128) | **JSON** | delete the file |
| Digimon placed in the maps (989 in 216 `.MAP` files: species, position, stats, moves, AI, path) | `content/maps/<FILE>.json` | **JSON** (`content.py extract-maps`); the `.MAP` keeps only the assets | delete a slot (a middle one: `"species": null`) or the file |
| Screens (`MAP_ENTRIES`: map file, TIM counts, sound bank, day/night, placed Digimon read, doors, toilet, caption) | `content/screens/<id>-<file>.json` (255) | **JSON** | delete the file (an empty entry) |
| Small tables of the executable: type factors, join chances, tournaments (calendar, opponent stats, win chances, medals), brain training, doors, toilets, cards and their prices, shop maps, shopkeepers, recyclables, Mojyamon's trades, Birdramon's transport, the starting inventories, sleep patterns, stat limits, babies, healing values, battle rules (retarget, stat gain), versus round counts, concave screens, map lights, fishing (fish kinds, bite chance, baits, the data of the two fishing maps), condition bubble offsets, aura rows, the gyms' training spots and which screens have them | `content/tables/` | **JSON** (the caps' stat limits from the compiled executable) | edit the values |
| Story (222 scripts, MAPHEAD) | `story/base/` (made from the disc once, owned source, keys only) + `story/mods/` | **source** | delete the script's folder or the event |
| Shops' stock, cup eligibility and rival lists, quests | the map scripts | **source** (story) | via the story |
| Dialogue and the executable's strings (item descriptions, menus, item and technique names) | `text/ours/` (our own translation, committed): every dialogue key (4727); the strings but 109 kept as built on purpose (digits, grade letters, blanks, fixed-position screen rows: `text/ours/README.md`) and the species names (from content/species) | **JSON** with `TEXT=ours` (strict build: 0 keys fall back) | — |
| Balance overrides (sparse edits on top) | `content/balance/*.json` | JSON | — |

The proofs: `balance.py verify` (72 tables byte-identical to what the JSON describes), `content.py diff` (0 tables
differ from the compiled executable), `species.py extract`/`sync` round-trips the evolution rows exactly.

## Maps

One `content/maps/<FILE>.json` per `.MAP` with Digimon (per file, not per script, since
193 scripts load 239 screens, some files have no script and one has two; the slot number links a placement to its script
and MAPHEAD, as an id links an item). The build writes the `.MAP`'s Digimon list from it over the disc's assets
(`content.build_map`); the story compiler starts from that (`backend.map_path`), and `balance.py build` puts the files that
changed on the disc. Slots are positional (scripts and MAPHEAD call them by number): a deleted middle slot is
`"species": null` (type 255, inert); only the last ones shrink the file. YAKA22 (63 declared, none parseable, never loaded)
is left as the disc has it.

Stats: each of hp, mp, off, def, speed, brain, bits is **nothing** (its species' `wild`), a **delta** (`"+200"`, `"-100"`)
or a **fixed** number. The disc species' `wild` is their most common placed stats (the original sets stats by area: 125
species placed with 278 stat sets), so 723 of the 989 slots write no stat at all and the rest are deltas. What equals the
usual value is left out (y 0, rotation x/z 0, script id 5 + slot, current HP/MP = HP/MP, unk2 0, unk1 1, flee y 0).
Proof: `content.py verify-maps` rebuilds the 242 `.MAP` files byte for byte.

**One species per slot** (`content.py lint`, run by the build): MAPHEAD's `spawn(Species.X, slot=k)` (`maphead/hooks.py`)
and a view's `npc(Species.X, slot=k)` must name the slot's species in content/maps, else the build stops (the engine's
`scriptSetDigimon` shows nobody when the type differs, silently). The `balance.py` `maps` layer is retired (an override of
it is an error pointing here). In the game, a delta `"hp": "+4700"` gives ModokiBetamon 5000 HP in battle; a screen with
a middle slot made a placeholder and the last one deleted (its story lines taken out) loads by day and by night, the
other slots spawn and the battles start. A slot added past the file's last sector (with its MAPHEAD spawn; the disc
built with `--relayout`) spawns, and the screens whose files moved load.

## Deleting

| What | Delete | What the build does | What stops the build (`tools/missing_refs.py`, `content.py lint`) |
|---|---|---|---|
| A species of the disc | its `content/species` file | empty rows; out of every evolution list and item (`balance.py`, `species.py`) | a `.MAP` slot of it; a story spawn, recruit, battle |
| An imported species | its file (or leave it out of `SPECIES`) | links to it dropped | — |
| A technique | its `content/techniques` file | empty `MOVE_DATA` row, learned nowhere | still in a species list (the position is the animation slot), a new-game technique, brain training; a story `learn` |
| An item | its `content/items` file | empty `ITEM_PARA` row (no name, not dropped, not sold), an evolution item gives nothing | a species' drop or favourite food; a story `give`/`spawn_item`/`spawn_chest`/`shop` |
| A script | its `story/base/zones/<zone>/sNNN.../` folder | an empty section table | — |
| A section | its event in the `script.py` | not in the table | — |

A section or script that does not exist runs nothing: patch 0112 makes `getScriptSection` return an `END_SECTION` instead of
the original's null pointer, which every caller ran as code. A question about something deleted (`recruited(...)`,
`has(...)`, `knows(...)`, `take(...)`, `== Item.X`) answers "no"; the story still compiles with the disc's names for ids
without a file. A saved game that holds one loads without it (patch 0114, `dropAbsentSaveContent` after `loadSaveCopy`): a partner whose
species row has no name becomes the first reincarnation baby that exists (stats and name stay; equipped animations and learned
bits are cleared, they were the old species'), an item with no name leaves the inventory, an equipped technique (the animation
id names the species' list slot) whose `MOVE_DATA` row is all zero is unequipped, and its learned bit cleared. With the rows emptied in RAM before
Continue: Agumon's row -> type 1 with no moves, an empty item 5 -> its slot freed and item 6 kept, an empty technique
row -> that slot 0xFF. Patch 0115 does the same for the registered Digimon of the VS mode
(`battleRegistrationData`, also on a card read for a VS match) and the item keeper's stock. A species new-game technique (`NEW_GAME_TECHNIQUES`) is
learned again by the game itself; `tools/missing_refs.py` also stops the build for an absent id in the C lists of `content/tables` (recycler, Mojyamon's trades, shopkeepers, starting inventories, babies, cards).

## Rules start empty in the C

The logic that was hardcoded holds **no literal rule** in the C. Its tables start with every slot at -1 ("the rule does
not exist") and `balance.py build` writes the numbers from the JSON on top (`NAMED_RULES` in `balance.py`: a table of
int16 or int32 slots and the JSON path of each). A key the JSON leaves out stays -1, so with no file the behaviour is
simply not there. `content.py extract` does not write these files (the C starts empty, the files are authored) and
`content.py diff` reports them as "rules the C starts empty" instead of as a difference. Each file's `_comment`
documents every key.

| `evolution-rules.json` | `evolutionTiming`, `evolutionFresh`, `evolutionUltimate`, `evolutionRules`, `evolutionSpecial`, `evolutionFormula` (patches 0117, 0118, 0131) | hours per level before a partner looks for an evolution (fresh 6, in-training 24, rookie 72, champion 144, ultimate 48), the Ultimate's second wait (96), the Mega wait (120), the Rookie fallback (after 96 h into species 11; no `hours.rookie` = a Rookie never evolves by time); the special evolutions (wake/praise rules and their conditions, the virus bar, the Champion hour, the scolding that arms Nanimon); the evolution formulas (blend and scale of stats, lifetimes, resets, learned technique window, the requirement score; the reset of weight, mistakes and battles is also `resetPartnerPara`'s, so deleting that rule does not stop it) |
| `medals.json` | `MOD_MEDALS` (patch 0120) | up to 16 rows `{medal, when: [kind, numbers], checkedBy: [tick|script], text, levelUp}`; the evaluator `modMedalHolds` is in tamer.c. The script routine skips a medal already owned and keeps looking (the original stopped at the first condition that held, owned or not, so medal 12 could become unreachable) |
| `tamer-level.json` | `MOD_TAMER_LEVEL` (patch 0121) | the chance of each event that moves the tamer level, the happiness marks of a year, the stats a rebirth inherits per level and the moves a lost life forgets |
| `tournament-rules.json`, `daily-rules.json`, `daytime.json` | patch 0122 | reminder times and sections, the Beetle cup, the STD remap and arena screen; the midnight card reroll (which also stops a card from repeating) and the counters; dusk/night/dawn, tint, music window, clock icon |
| `training.json`, `vs-unlock.json` | patch 0123 | gain multiplier by training type and level, plus the Kabuterimon, Kuwagamon, upgrade-counter and training-manual bonus rows (proven equal to the original over 38400 cases); the VS unlocks |
| `care-rules.json` | `MOD_CARE`, 150 slots (patches 0125, 0130, 0140) | the periods, thresholds and amounts of the partner's daily care: sleep, sulking, area effects, tiredness, hunger, poop, sickness, the lifetime lost to unhappiness, scold and praise, item refusal, clamps, babies' awake/hunger, sleep costs and regeneration, feeding, toilet, poop eaten (species 11 and 39, radii `reachNear` 200 / `reachFar` 300), skipped hours, what a fight costs. | `effect-donors.json` | efe.c's `MOD_DONOR_*` (patch 0116) | which species borrows another's effect points, with the origins and bone maps (fixed room for 16 entries, 24 origins, 48 bones) |

**Time.** Everything is written in game time: the care rules give a time as game seconds or as text with units
(`"45s"`, `"10m"`, `"1h"`, `"1h30m"`; steps of 3 s), so a longer or shorter day changes how fast the partner gets
hungry, sleepy or sick without touching them; a species' `care` override takes the same forms (`"+10m"`, `"-30s"`,
`"-20%"`). The game frame is 1/20 of a game minute (3 game seconds); the clock accumulates the frames of each logic tick
(20 ticks a second) and runs them one by one; `CURRENT_FRAME % period` tests are crossings (a script's jump in time
crosses nothing). **Every wait of the fight and of fishing is in real milliseconds** (one logic tick every 50 ms at any
frame rate; `balance.py` turns a time into ticks and rejects one that is not a multiple of 50): `block.invulnerableMs`,
`status.poisonIntervalMs`, `confusionMs`/`confusionExtraMs`, `stunMs`, `flatMs`, `cooldown.afterAttackMs`/`noTargetMs`,
`senile.durationMs`/`intervalMsPerStep`, `flee.ignoreHitsFromMs`/`lockMs`, `speed.stepMs`, `buffs.priorityStepMs`,
`flatten.*Ms`, `approach.*Ms`, `defeat.*Ms`, `finisher.holdMs`/`chargeWindowMs`, `afterFight.settleMs`. The VS
overlay's own combat code (`vs_combat.c`) reads the table too.

**Saves** (patch 0129): the extension of a save file is a list of tagged records (`u16 tag, u16 length, data`;
`include/dw/save_tags.h`), so changing how many species, flags or items the game has, or adding state, never makes an
older save unreadable: a record is copied as far as both sides have room, an unknown one is skipped, an unknown
*required* one (the tier-2 story state) makes a build refuse the file instead of dropping it. The v1 part of the file
(the original game's layout) stays frozen; what is new goes into records. Saves of formats 1, 2 and (tier 2) 3 still
load and are written as v4 (tier 2: v5) at the next save.

**Left in code on purpose** (state machines, dispatch, animation, not numbers): the condition bits, the death script
section and entry points, the sleep-hour arithmetic (`timeAwakeToday` counts ten-minute steps of the day), the condition
bubbles' timers, the flatten squash of 65 ticks (the `case 0x40` / `case 3` of three overlays and `applyFlattenScale`'s
curve are tied to it), the confused fighter's turning, the random camera cuts, the player's command delay (dormant in
the original), the pulse of a countdown digit, `initializeMap`'s `CURRENT_EXIT = 9` ("no exit" marker), the new-game
conversation, the credits/movie sequence, Item Keeper, the gyms' flow, the VS menu, `CALL_ROUTINE` dispatch, the
game-clear save, the story's trigger and pstat numbers that C reads. The sickness chance keeps the original's unsigned
byte (a negative result wraps and makes the partner sick). Not changed: `REDUCE_MERIT` sets merit to 0 instead of
subtracting (an original bug that story scripts may rely on). An older table whose file is deleted falls back to the
disc's values (only the rules above and the curling tables start empty).

## Other initialized data

An audit of the executable's 3142 initialized data objects (each checked against its uses in the sources) leaves no
content table besides what is above, and these:

- **Rows that mix data and addresses** (`balance.py KEEP`): `FISHING_MAP_DATA` (scales, times, cast range: JSON in
  `fishing.json` `fishingMaps`) and `TRN_TRAINING_SPOTS` (`spotScreens` in `training-spots.json`) are written field by
  field: the data fields come from the JSON, the address fields (spot lists, water test, sprite path, waypoints and
  their counts) stay as the compiled executable has them. The row counts cannot grow (2 fishing maps; 7 training screens
  + terminator), and a spot list belongs to its row by position. What stays C: the fishing spots' points, Seadramon's
  waypoints, the water-test functions. `FISHING_DATA` is run-time state (bss), not content.
- **The lab menu's NPC partner list**: code of the mod, tied to the lab menu.
- **Text**: the strings and their pointer tables (`ITEM_DESCS`, `MOVE_NAMES`, medals, tamer titles, map names, the
  jukebox, the kart minigame's lines) are the text source's (`text/ours/names.json`); the shown names of items and
  techniques are text too (content's `name` is the tools' identifier).
- **The release bundle** carries `content/`, `story/base` and `decomp/config/us`; every part rebuilt in a clean tree
  from the bundle alone matches.
- **Saves**: a saved game that holds a species, item or technique without a file loads without it (patch 0114,
  "Deleting").

About 600 more objects are presentation (layouts, colours, cameras, skeletons, embedded models and textures, the
overlays' copies of UI tables) and about 40 are run-time state with an initial value: not content.

## Never JSON

- **Behaviour in C**: what an item does (`ITEM_FUNCTIONS`), evolution timers and formulas, care rules, the battle
  formulas, special evolutions, the training rewards (`trn_reward.c`): code, changed by C patches (`mods/patches`),
  with their numbers in the rule tables above.
- **Assets**: models, textures, backgrounds (`.TFS`, the `.MAP` TIMs), sounds and music.
